# Pathfinder UCD 实验设计（v0.3，2026-11-18）

研究问题：**按学校职责（校级 / 学院 / 系）组织的多 Agent，在模糊的学业咨询请求上，是否比拿到同样资源的单个工具型 Agent 回答得更好？代价多大？** 不预设复杂架构一定更好。

## 1. 两个条件

| | A · 单 Agent（ReAct） | B · 多 Agent（Personal + 专家） |
|---|---|---|
| 角色 | 一个 Advisor 负责一切：追问、检索、核对先修、比较路径、准备顾问问题 | Personal 负责对话与共享记录；7 个专家各管一层：University、College·L&S、College·CoE、Dept·ECS/PSC/LIN/MAT |
| 检索 | 全库检索，可自己加 `level/unit` 过滤 | Personal 不检索；每个专家**硬限制**只能检索自己 unit 的文档 |
| 交接 | — | Personal `delegate`；专家可在报告里 `handoff` 给另一层（经控制器、深度 ≤2、去重、全部记日志） |
| 上下文 | 一个上下文累积所有观察 | 专家只拿到：聚焦问题 + 共享 JSON 记录中的已确认事实 + 已有结论与证据 ID，不看原始对话 |
| 学生 | 可直接追问 | 只有 Personal 能追问；专家返回 `missing` |

**严格对齐的资源**（`src/core/types.ts` `defaultBudget`，开发集上确定后冻结）：

| 资源 | 值 | 说明 |
|---|---|---|
| 总 tokens（输入+输出） | 70,000 | B 的所有调用（Personal、专家、修复）都计入同一账本 |
| 模型调用 | 18 | 同上 |
| 工具调用（检索+课程查询） | 14 | |
| 学生追问 | 5 | |
| 专家调用（仅 B） | 6 | 每次专家最多 3 步 |
| 单步输出上限 / 最终 | 900 / 2,200 | |

同一模型、温度 0.2、同一证据库、同一最终报告 schema、同一证据规则文本（`EVIDENCE_RULES`）。预算将尽时两组都被强制收尾；超出时输出保守报告，不崩溃。

## 1b. 信息清单（Information checklist，v0.4 新增）

目的：让 Agent 每一轮都先判断"已经知道什么、还缺什么"，只针对缺口继续查询，避免过度查询，并把进度实时展示出来。A、B 两组使用**同一个**清单控制器（`src/core/checklist.ts`），因此仍是公平对比；它也可以在实验设置里整体关闭，作为一个实验因子（清单开/关 × A/B）。

```
学生开场 ──► 主 Agent 第一轮：列出 3–6 项信息需求
               q1 [student] 学生现在是哪个学院/专业？
               q2 [policy]  AP Calculus AB 3 分能换什么学分？ …
每一轮：主 Agent 输出 action + target(本步针对哪一项) + checklist_update
          │
          ▼
控制器校验 ──► policy 项标"已解答"必须引用本次真实检索到的证据 id
            └► student 项标"已解答"必须引用学生原话（在开场或回答中逐字出现）
            不满足 → 降为"部分"，并把驳回原因写回给 Agent
          │
          ▼
状态板（附在下一轮观察末尾）：✓ 已解答 ◐ 部分 ○ 待查 ✕ 需顾问，及下一步提示
  · 全部解决 → "不要再查，直接作答"
  · 针对已解决项的检索/追问/委派 → 记为多余动作并警告
  · 预算将尽 → 研究关闭，只允许给出最终答复（再次不遵守则直接收尾）
```

B 组中，Personal 委派任务时会带上所针对的清单项（`[q2] …`），专家据此聚焦；状态仍由 Personal 更新、控制器校验。

新增指标：**信息清单完成度**（最终已解答/需顾问的比例）、**多余查询动作数**；轨迹里的每次 `checklist` 事件保存完整快照，界面可回放清单随时间的变化。

## 2. 证据库（`corpus/`）

- 42 个官方页面，2026-11-18 抓取（`scripts/scrape.py`，保存原始 HTML、SHA-256、抓取时间）：Catalog 的 AP/IB、成绩与 P/NP、学业状态、加退课、学分上限、GE；Registrar 转专业；L&S 与 CoE 的学位要求、转专业、P/NP、最低进度；CS、Psychology（Yellow Cluster）、Linguistics、Math 各专业/辅修与宣布专业页面。
- 本地 SQLite：`changemajor.db` 的 7 条转专业记录（标记为 **LEGACY**，用于考察"旧来源 vs 新来源"）、`ucdavis_calendar.db` 的 2026-27 校历、`courses.db` 的 1,061 门课（ECS/PSC/LIN/MAT/STA/PHY/CHE/BIS/COM/CGS，含先修与非官方评价）。
- 共 53 份文档、545 段。每段带 `level`/`unit`，这是 B 组检索隔离的依据。数学系现网页没有写宣布专业门槛，只有旧记录（2.7 GPA）——这是刻意保留的"需要向顾问确认"的情形。

## 3. 情景（`experiment/scenarios.json`）

24 个虚构案例：**4 个开发 + 20 个留出**（5 类 × 4）。每个都以不完整的开场白开始，至少组合两个因素，覆盖 ECS / PSC / LIN / MAT、大一到大四与转学生、中英文开场。

| 类别 | 留出案例 |
|---|---|
| 兴趣不明确 | H-U1 儿童语言（心理 vs 语言学）· H-U2 CS 学生偏爱证明 · H-U3 语言学大三想做 NLP（中文）· H-U4 数学+助人 |
| 准备情况不确定 | H-P1 AP CS A + Calc BC 4 · H-P2 AP Psych 4 + 双录取课程 · H-P3 IB Math · H-P4 母语中文与外语要求（中文） |
| 学业负担取舍 | H-W1 打工 20h + 17 学分 · H-W2 心理 B.S.→A.B. · H-W3 第 5 周 MAT 21D 挂科风险 · H-W4 心理+语言学双专业且打工 |
| 要求交叉重叠 | H-O1 Math+Applied Math（同系不许）· H-O2 心理+CS 跨学院（MAT 21B 是 P/NP）· H-O3 语言学+心理辅修 · H-O4 数学转学生想转 CS |
| 程序/期限风险 | H-R1 CS 学业察看想转心理 · H-R2 未定专业 88 学分 · H-R3 大四 205 学分想加数学（中文）· H-R4 ECS 36B 拿 D |

每个案例包含：
- **隐藏档案**：5–7 条事实（`critical` 标出会改变建议的事实），只有被问到才透露。
- **评分清单**（事先写好，评测前冻结）：6–9 项，权重 1 或 2。
- **参考要点**：给人工评分者的"好答案长什么样"，允许多种合理建议。

## 4. 模拟学生

`simulatedStudent`：温度 0 的匹配器只决定"这个问题在问哪些事实 ID"（≤3 条），回答文本是案例里**固定的原文**。所以两组对等价问题听到完全相同的回答；模拟器 token 单独记录，不计入任何一组预算。也可选"研究员手动答复"模式：界面显示隐藏档案，研究员勾选透露的事实（同样计入 `disclosed`）。

## 5. 评分：怎么量化

**主指标：清单满足率**（加权，0–100%）。每项得 0 / 0.5 / 1：

| 类型 | 判定方式 |
|---|---|
| `elicit` 追问到关键事实 | **自动**：对应事实是否被透露（模拟器日志） |
| `cite` 核对了某来源 | **自动**：最终报告中有来自该文档的**有效引用** = 1；只检索过未引用 = 0.5；没检索 = 0 |
| `next_step` / `caution` / `referral` / `avoid` | **盲评 Judge**（不知组别，只看报告 + 隐藏档案 + 清单 + 所引证据原文） |

规则：
- **有效引用** = 证据 ID 存在且本次运行确实检索到过；否则记为无效引用。
- **空洞谨慎惩罚**：若没有任何一个路径选项带有效证据，所有 `next_step` 项记 0（防止"一律让你问顾问"拿分）。
- **无依据关键论断**：报告中 `critical` 的规则陈述，若无有效引用记 `uncited`；有引用则由 Judge 对照证据原文判 supported / partial / unsupported / contradicted。unsupported + contradicted + uncited 计数。

**次要指标**（`src/core/analysis.ts` `METRICS`）：无依据关键论断数、关键事实获取率、有效/无效引用数、重复检索、追问次数、tokens、模型调用、工具调用、模型耗时、总耗时；B 组另报告交接次数与被拒交接。

**人工盲评**：导出盲评包（只有案例、清单、匿名总结、随机 blindId），两位组员各独立给 ≥16 份评分，导入后计算两人之间、以及人与 Judge 之间的一致率、Cohen's κ 和线性加权 κ；分歧讨论后定稿。Judge 与被测模型同为 DeepSeek 是已知局限，可用 `--judge-model` 换一个模型复评。

## 6. 运行与对比

- 20 个留出案例 × 2 次重复 × 2 组 = **80 次运行**（提案中 16 案例 = 64 次，此处每类多 1 个案例；可在界面或 CLI 选子集）。
- 排程：每个（案例, 重复）内 A/B 先后随机，再把所有对打乱交错（`schedule`，固定种子 2026），盲评 ID 由同一种子生成。
- 分析单位是**案例**：先对每个案例内两次重复取平均，再算配对差 **B − A**：均值、10,000 次 bootstrap 95% CI、双侧符号翻转置换检验 p（n ≤ 18 精确枚举，否则 20k 蒙特卡洛）、配对效应量 dz、B 更好/持平/更差的案例数；按类别拆分；报告两次重复间的波动（稳定性）。
- 定性：检查 B 组交接中**信息增益**（专家补出关键条件）与**信息丢失**（共享记录漏掉事实、专家结论没进最终报告）的典型轨迹。
- 结论只代表这套完整设计的对比，不拆分单个专家的贡献；结果是探索性的，不代表真实咨询效果。

## 7. 流程（冻结点）

1. 开发集 4 案例上调预算和提示词 → 记录 `PROMPT_VERSION`、语料版本 `corpus.version`。
2. **冻结**提示词、预算、清单、评分规则后，才跑留出集。
3. 跑 80 次 → 自动评分 → 导出盲评包 → 两人评 ≥16 份 → 导入算一致性 → `npm run analyze` 出报告。

## 8. 效度威胁

- 模拟学生只回答固定事实，比真实学生更配合；手动模式可作补充。
- Judge 与被测模型同源；有人工盲评与可换 Judge 两道校验。
- 语料是 2026-11-18 的快照；课程记录来自 2025-08 的本地数据库；旧转专业记录无日期。
- 引用校验只证明"引用的段落存在并被检索过"，语义支持由 Judge/人工判断。
